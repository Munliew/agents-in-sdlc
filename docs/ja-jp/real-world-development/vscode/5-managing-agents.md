Copilot を agent mode で使うと、コードベースの調査、変更の提案、ファイルの編集、コマンドの実行を自律的に行います。VS Code の Copilot Chat では、ツールの呼び出しやファイルの編集をリアルタイムに確認できます。差分をインラインでレビューし、個々の変更を採用または取り消し、フォローアップのプロンプトで会話を調整できます。エディターを離れる必要はありません。

この演習では、次のことを行います。

- アクセシビリティエージェントの作業をリアルタイムで監視します。
- 提案されたファイル編集を確認して採用します。
- セッション中にエージェントへ指示し、ハイコントラストに加えてライトモードのトグルを追加します。

## シナリオ

[演習 4][previous-lesson]で使ったアクセシビリティカスタムエージェントが、ハイコントラストモードを実装しています。作業中、デザインチームから追加の要望がありました。既定のテーマが暗すぎると感じる利用者向けに、ライトモードのトグルも追加したいとのことです。新しい会話を始めずに、既存のセッションに指示して作業を拡張します。

## Copilot の進捗を監視する

Copilot Chat ビューには、エージェントが調べたファイル、実行したコマンド、提案した編集などの各ステップが表示されます。編集は差分と **Keep** / **Undo** の操作とともにチャット内に表示されます。

1. 演習 4 で使った Copilot Chat ビューに戻ります。
2. エージェントが作業している間、チャットをスクロールして各ツール操作を確認します。ファイルの読み取りと編集、実行を求められたターミナルコマンドが表示されます。
3. エージェントがファイルの編集を提案すると、差分がチャットに表示されます。
   - 変更を採用するには **Keep** を選択します。
   - 変更を取り消してエージェントに再度作業させるには **Undo** を選択します。
4. チャット上部の **Files changed** を開き、セッション中にエージェントが変更したファイル全体を確認することもできます。

> [!NOTE]
> ターミナルコマンドの実行などで許可が必要な場合、エージェントは一時停止して **Allow** を表示します。内容を確認し、許可してもよいコマンドだけを承認してください。

5. エージェントがハイコントラストモードの実装を終えるまで待ちます。完了すると、変更内容の概要が表示されます。

## エージェントにライトモードを追加するよう指示する

ハイコントラストモードができたら、同じ会話でライトモードのトグルも追加します。同じセッションを続けることで、エージェントは前の作業で扱ったコンポーネント、スタイルの方針、local storage の使い方を引き継ぎます。

1. Copilot Chat の入力欄に、次のフォローアッププロンプトを送信します。

   ```plaintext
   ありがとうございます。ハイコントラストのトグルに加えて、ライトモードのトグルも追加してください。同じ方法で local storage に設定を保存し、同じ UI 領域から操作できるようにしてください。ハイコントラストとライトモードは、それぞれ独立して有効化できるようにしてください。
   ```

2. エージェントが既存の変更を確認し、ライトモードの追加を提案する様子を確認します。
3. ハイコントラストと同様に、新しい編集を確認して **Keep** または **Undo** を選択します。
4. トグル UI を意図しない形で再構成するなど、エージェントが期待と異なる方向に進んだ場合は、チャット入力欄の隣にある **Stop** で停止し、明確な指示を追加します。

> [!TIP]
> 進行中のセッションに指示する方が、最初からやり直すより早く済みます。フォローアップで「CSS を簡素化して、セレクターの重複ではなく CSS 変数を使う」「3 つ目のトグルを追加せず、既存の設定パネルにライトモードを加える」「両方のトグルにキーボードショートカットを追加する」などと調整できます。

## 変更されたファイルを確認する

コミットする前に、エージェントが変更したファイルを確認します。

1. VS Code で **Source Control** ビューを開きます。
2. 変更されたファイルの一覧を確認します。Astro コンポーネント、スタイル、関連テストなどが含まれます。
3. 変更されたファイルをいくつか開き、差分を確認します。カスタムエージェントが示したアクセシビリティの指針、Accessible Rich Internet Applications (ARIA) 属性、キーボード操作、セマンティック HTML、local storage による設定の保存が反映されていることを確認します。
4. 問題がなければ、Source Control パネルで変更をステージしてコミットします。次のレッスンで公開します。

## まとめと次のステップ

Copilot Chat の agent mode を使い、進行中のセッションを監視して方向を示しました。ファイル編集を確認して採用または拒否し、コンテキストを失わずにフォローアップを送って作業を拡張しました。

この演習では、次のことを行いました。

- エージェントの作業をリアルタイムで監視しました。
- 個々のファイル編集を確認し、採用または取り消しました。
- フォローアップで進行中のセッションに指示し、作業を調整しました。

次の[レッスン][next-lesson]では、アクセシビリティの変更をプルリクエストとして公開し、このワークショップでローカルのカスタムエージェントが生成した変更を確認します。
