GitHub Pages で Space Quiz をデプロイし、誰でもアクセスできる場所に公開します。Copilot はワークフローの準備とデプロイを支援しますが、変更をレビューし、サイトが公開されたことを確認するのは開発者の役割です。

このレッスンでは、次のことを行います。

- Copilot に GitHub Pages のデプロイ設定を依頼します。
- マージする前にワークフローとプルリクエストをレビューします。
- デプロイの進行状況を確認し、公開されたサイトを検証します。

## シナリオ

Space Quiz はすでに GitHub リポジトリにありますが、誰もが簡単に試せる場所が必要です。単一ファイルのサイトを GitHub Pages で公開すれば、サーバーやランタイム依存関係を追加せずに公開 Uniform Resource Locator (URL) から利用できます。

## Copilot にサイトのデプロイを依頼する

`space-quiz` の Copilot app セッションで、GitHub Pages を設定してデプロイするよう Copilot に依頼します。

1. 次のプロンプトを送信します。

   ```plaintext
   このリポジトリで GitHub Pages を有効にしてください。必要に応じて Web サイトをビルドし、GitHub Pages にデプロイする GitHub Actions ワークフローを作成してください。README がまだない場合は、アプリの説明とローカルでの実行方法を記載した README を追加してください。これらの変更でプルリクエストを作成し、必須チェックの成功後にマージしてください。デプロイが成功するまで監視し、公開サイトの最終 URL を報告してください。Pages の有効化またはマージの権限がない場合は、必要な承認や作業を具体的に説明してください。サイトが公開されるまでは成功を報告しないでください。
   ```

> [!WARNING]
> このプロンプトは、エージェントにプルリクエストの作成とマージ、およびリポジトリの Pages 設定の変更を依頼します。続行する前に差分、デプロイ権限、GitHub の承認要求を確認してください。

## ワークフローをレビューしてデプロイを確認する

1. README は、リポジトリにまだ存在しない場合にのみ追加されていることを確認します。
2. ワークフローのビルド手順とデプロイ手順を含め、プルリクエストの変更をレビューします。
3. 必須のプルリクエストチェックが成功した後にのみマージします。
4. GitHub Actions のデプロイ実行が成功するまで確認します。
5. 報告された URL を開き、Space Quiz が読み込まれることを確認します。

エージェントが Pages の有効化やプルリクエストのマージを行えない場合は、エージェントの具体的な指示に従ってください。デプロイが成功し、公開サイトが読み込まれるまでは完了とみなさないでください。

- Copilot に GitHub Pages のデプロイ設定を依頼しました。

- デプロイの進行状況を確認し、公開されたサイトを検証しました。
